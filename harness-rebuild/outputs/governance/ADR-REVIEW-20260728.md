# ADR-001~007 一次性确认材料

状态：全部仍为 `proposed`；本文件只供确认，不改变决策状态。

## 七条摘要

1. **ADR-001**：只使用通过握手的云端旗舰原生工具；失败不降级到双阶段或宿主代搜。
2. **ADR-002**：终态使用“结果 × 原因”两轴，并由合法组合表拒绝矛盾状态。
3. **ADR-003**：预算耗尽后只有真实综合成功才是 `partial`；修复耗尽必须是 `failed/protocol_error`。
4. **ADR-004**：只有实际读取的原文片段有引用资格；搜索轨迹与命中元数据不得生成引用。
5. **ADR-005**：作用域由宿主冻结；模型不能传 scope；`readableIds` 由 TS 与 Rust 双侧校验。
6. **ADR-006**：事件带 `schema_version` 并事务落库；旧 turn 只读；完整审计历史与模型压缩工作集分离。
7. **ADR-007**：重试按错误分类；协议修复只做无损确定性操作，有歧义要求同一模型重发。

## 一致性检查

结论：未发现直接冲突。

- ADR-002/003 定义合法终态及 `partial`/`protocol_error` 分界。
- ADR-004/005 定义证据资格与不可越权读取边界。
- ADR-006 为前述状态、证据和恢复提供持久事件基础。
- ADR-007 的最终失败落入 ADR-002/003 的 `failed/protocol_error`，不制造假成功。
- ADR-001 禁止用降级路径绕开 ADR-003/007 的失败语义。

## 实施约束

- TASK-007 承担 ADR-005 的 Rust `readableIds` 全局校验；TASK-012 只做附件生命周期。
- TASK-004~010 全绿后，TASK-011 仍需用户即时确认才允许删除旧双阶段路径。
